When emails are not reaching your recipients, work through the steps below to identify and fix the issue.

---

## Quick Diagnostic Checklist

<Tip>
  If [Adamko](/learn/ai-assistant/troubleshooting-and-diagnostics) is enabled in your account, he runs this entire checklist in one question: *"why didn't jane@acme.com receive my email?"* checks the recipient's events, the suppression list, and your domain state, and returns a single root cause with evidence. The manual steps below remain the way to verify things yourself.
</Tip>

<Steps>
  <Step title="Check your domain status">
    Open the [Domains page](https://app.lettr.com/domains) in the Lettr dashboard. Your sending domain must show a status of **approved** and all DNS records must be **valid**. If anything shows `pending`, `unverified`, or `invalid`, resolve that first.
  </Step>
  <Step title="Check the suppression list">
    Ask [Adamko](/learn/ai-assistant/troubleshooting-and-diagnostics) whether the recipient address is suppressed, or search for it on the **Events** page and look for an earlier bounce or spam complaint. If the address is suppressed, Lettr will not attempt delivery.
  </Step>
  <Step title="Check the email status">
    Go to **Events** in the dashboard and search for the recipient address. The event history and any error details will tell you whether the email was accepted, delivered, bounced, or failed to send.
  </Step>
  <Step title="Review bounce messages">
    If the email bounced, expand the event details in the dashboard to see the SMTP response code and message returned by the recipient server. These codes are explained further below.
  </Step>
</Steps>

## Common Issues

<AccordionGroup>
  <Accordion title="Domain Not Verified">
    Lettr requires a verified sending domain before it will transmit any email. If your domain status is `pending` or DNS records show `unverified` / `invalid`, emails will fail with an `unconfigured_domain` error.

    **To fix this:**

    1. Open the [Domains page](https://app.lettr.com/domains) in the dashboard.
    2. Click on the domain in question and review the required DNS records (DKIM and DMARC, plus SPF for a root domain or a CNAME for a subdomain).
    3. Add or correct the records with your DNS provider.
    4. Click **Verify DNS Records** in the dashboard, or trigger verification via the API:

    ```bash
    curl -X POST https://app.lettr.com/api/domains/yourdomain.com/verify \
      -H "Authorization: Bearer lttr_xxxxxxxxxxxx"
    ```

    You can also check the current domain status:

    ```bash
    curl https://app.lettr.com/api/domains \
      -H "Authorization: Bearer lttr_xxxxxxxxxxxx"
    ```

    <Note>
      DNS changes can take up to 48 hours to propagate, though most resolve within minutes.
    </Note>
  </Accordion>

  <Accordion title="Recipient Suppressed">
    If a recipient hard-bounced or filed a spam complaint, the address is added to your suppression list, and later sends to it are rejected and counted in the `rejected` total of the API response. Unsubscribes work differently: a campaign unsubscribe only changes the contact's status, and an unsubscribe entry on the suppression list only blocks sends with `transactional: false`. See [Unsubscribes, Pauses and Suppressions](/knowledge-base/fundamentals/unsubscribe-vs-suppression).

    There is no suppressions page in the dashboard and no API endpoint for suppressions. To check an address, ask [Adamko](/learn/ai-assistant/troubleshooting-and-diagnostics) *"is jane@acme.com suppressed?"*, and he reports why and when it was suppressed. A suppression can't be lifted from the dashboard or API. If the original reason no longer applies (the recipient re-opted in, or you fixed the cause of a hard bounce and confirmed the mailbox is valid), email [support@lettr.com](mailto:support@lettr.com) with the address and what has changed. Removal is reviewed case by case and is unlikely for spam complaints.

    <Warning>
      Repeatedly sending to addresses that have hard-bounced damages your sender reputation. Only ask for a suppression to be lifted if you have confirmed the mailbox is valid again.
    </Warning>

    See [Bounce Suppressions](/learn/suppressions/bounces) for more detail on how Lettr handles suppression rules.
  </Accordion>

  <Accordion title="Spam Filters Blocking">
    If your email is delivered but lands in the spam folder, the problem is not a Lettr delivery failure — it is a placement issue driven by content, authentication, or reputation.

    See [Troubleshooting Spam Placement](/knowledge-base/troubleshooting/spam-placement) for a full guide on diagnosing and fixing spam folder placement.
  </Accordion>

  <Accordion title="Rate Limited">
    If you are sending a high volume of emails in a short period, you may encounter rate limiting. Lettr returns an HTTP `429` status when the limit is reached.

    See [Rate Limits](/knowledge-base/troubleshooting/rate-limits) for details on current limits and strategies for handling them.
  </Accordion>

  <Accordion title="Invalid From Address">
    The `from` address in your API request must use a domain that is verified in your Lettr account. If it does not, the API will reject the request.

    Possible error codes:

    | Error Code | HTTP Status | Meaning |
    |---|---|---|
    | `validation_error` | 422 | The `from` field is missing or malformed. |
    | `invalid_domain` | 400 | The sender domain could not be determined from the `from` address. |
    | `unconfigured_domain` | 400 | The domain isn't added to your team, isn't approved, or its DNS records aren't all valid. |

    Make sure your `from` address matches a domain with **approved** status and **valid** DNS in the dashboard.
  </Accordion>
</AccordionGroup>

## Checking Email Status

The fastest way to check the status of a specific email is through the **Events** section of the Lettr dashboard, where you can search by recipient address and open the full event history of each message.

An email can also be retrieved by the request ID returned when it was sent:

```bash
curl https://app.lettr.com/api/emails/{requestId} \
  -H "Authorization: Bearer lttr_xxxxxxxxxxxx"
```

The response will include the current delivery status and any error information associated with the message.

## Reading Bounce Messages

When a recipient server rejects an email, it returns an SMTP status code. Lettr surfaces these codes in the dashboard and through the `message.bounce` webhook event. Here are the most common codes and what to do about them:

| SMTP Code | Meaning | Action |
|---|---|---|
| `550 5.1.1` | Mailbox does not exist. | Remove the address from your list. This is a hard bounce and the recipient is automatically suppressed. |
| `550 5.7.1` | Message rejected by policy (spam, authentication, or block). | Check your SPF/DKIM/DMARC records and review your email content for spam triggers. |
| `452 4.2.2` | Mailbox full. | This is a soft bounce. Lettr will retry automatically. If it persists, the recipient may have abandoned the mailbox. |
| `421 4.7.0` | Temporary rate limit from the recipient server. | No action needed. Lettr will retry delivery. If the problem persists across many recipients at the same domain, slow your sending rate. |

Bounces can be handled programmatically using webhooks. The `message.bounce` event includes the bounce class and SMTP details:

```javascript
const express = require("express");
const app = express();

app.use(express.json());

app.post("/webhooks/lettr", (req, res) => {
  // Lettr delivers events in batches, as an array
  for (const event of req.body) {
    const data = event.msys?.message_event;

    if (data?.type === "bounce") {
      console.log(`Bounce for ${data.rcpt_to}`);
      console.log(`Class: ${data.bounce_class}`);  // 10, 30, 90 = hard
      console.log(`Code: ${data.error_code}`);
      console.log(`Message: ${data.raw_reason}`);

      if (["10", "30", "90"].includes(data.bounce_class)) {
        // Remove address from your mailing list
      }
    }
  }

  res.sendStatus(200);
});

app.listen(3000);
```

## Testing Deliverability

Send a test email to an address you control to confirm your setup is working end to end:

```bash
curl -X POST https://app.lettr.com/api/emails \
  -H "Authorization: Bearer lttr_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "test@yourdomain.com",
    "to": "you@example.com",
    "subject": "Lettr delivery test",
    "html": "<p>If you can read this, delivery is working.</p>"
  }'
```

Check your inbox (and spam folder). If the email arrives, your domain and authentication are configured correctly. If it does not, work through the diagnostic checklist above.

## Still Having Issues?

If you have worked through the steps above and emails are still not being delivered, contact the Lettr support team at **[support@lettr.com](mailto:support@lettr.com)**. Include the email request ID (returned in the API response when you sent the email) so the team can investigate quickly.
