The [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) is an open standard that enables AI assistants to securely connect with external services. Lettr provides two MCP servers so AI agents can interact with your email infrastructure — sending messages, managing templates, configuring domains, and monitoring delivery — all through natural language.

## Why Use MCP?

MCP transforms how you interact with your email infrastructure. Instead of switching between dashboards, writing code, or memorizing API calls, you can ask your AI assistant to handle email tasks directly.

| Traditional Workflow | With MCP |
|---------------------|----------|
| Open dashboard, navigate to domains, check verification status | "Check if my domain example.com is verified" |
| Write code to send an email via API | "Send a test email to john@example.com" |
| Query API logs, parse response, identify issues | "Why didn't my email to jane@example.com deliver yesterday?" |
| Browse events, filter by recipient, analyze patterns | "Show me recent bounces for the last 24 hours" |

## One Server, Two Ways to Authenticate

Lettr's MCP server is hosted at `https://app.lettr.com/mcp`. It accepts either credential, and which you use depends on whether a person is present.

### Comparison

| | OAuth | API key |
|---|---|---|
| **Needs a browser** | Yes, once | No |
| **Acts as** | You, the person | The team the key belongs to |
| **Scoped access** | Full account access | Limited to the key's permissions |
| **Team selection** | `team_id` per call, or pinned in client config | Fixed by the key |
| **Best for** | Interactive chat, personal use, account-wide tasks | CI, cron, scripts, headless agents, restricted access |

### Which Should I Use?

**OAuth** for your own interactive use — in Claude, ChatGPT or your editor. There is no key to create or store, and access follows your own account.

**An API key** when no human is present to click through a sign-in, or when you want an agent restricted to part of your account: a sending-only key can send email and nothing else, and a sandbox key cannot write at all.

<Tip>
  You can use both. Add two server entries with different names if you want an interactive connection and a restricted one side by side.
</Tip>

## What Can You Do?

The hosted server covers sending, templates, folders, projects, domains, webhooks and the whole audience surface — contacts, lists, topics, properties and segments — plus analytics, email events and API logs. See the [tools reference](/learn/mcp/tools-reference) for the full list.

What a given connection sees depends on its credential: an OAuth caller gets everything, while an API key sees only the tools its permissions cover, and never the API-key or log tools.

## Example Conversations

Once connected, you can interact with your email infrastructure using natural language:

**Sending emails:**
> "Send an email to john@example.com from hello@mycompany.com about tomorrow's 3pm meeting"

**Using templates:**
> "Send the 'order-confirmation' template to buyer@example.com with order_id '12345' and customer_name 'Sarah'"

**Debugging delivery:**
> "Why didn't my message to jane@example.com deliver yesterday?"

**Checking domains:**
> "Is my domain notifications.example.com verified and ready to send?"

**Reviewing events:**
> "Show me all bounces from the last week"

## Security

- **OAuth** ties access to your Lettr session and team permissions. Sign out and the AI loses access. No API key is ever exposed to the assistant.
- **API keys** are scoped: [restrict a key's permissions](/learn/api-keys/permissions) so an agent can only do what you intended, restrict it by IP, or use a sandbox key, which cannot write and can only send to your own address. A key in a client config file is a password in plain text, so keep those files out of version control.

<Warning>
  MCP allows AI assistants to send emails on your behalf. Only connect trusted AI clients and review actions before confirming sensitive operations.
</Warning>
