This reference lists every tool on Lettr's [remote MCP server](/learn/mcp/setup), grouped by what it works on. Each tool does exactly what the matching [API endpoint](/api-reference/introduction) does, and your AI client receives each tool's full input schema when it connects, so you never have to pass parameters by hand. Just describe what you want.

The [local server](/learn/mcp/local-setup) (`lettr-mcp` npm package) offers the same tools with a few differences, listed under [Local server differences](#local-server-differences).

## Destructive Tools and Permissions

Tools marked **Destructive** send email, overwrite data, or remove data in a way that can't be undone. They carry the MCP destructive annotation, so clients such as Claude can ask you before running them. Read-only tools are annotated as read-only.

Every tool runs as you, in the team currently selected in your Lettr account, and goes through the same team permission checks as the dashboard. The AI can never reach another team's domains, templates, contacts, or campaigns.

<Warning>
  A confirmation prompt is only as good as your review of it. Before approving a destructive tool, check the recipients, the audience, and the IDs it is about to act on, especially for `send_campaign` and the bulk audience tools.
</Warning>

## Emails

| Tool | What it does | Destructive |
|-|-|-|
| `send_email` | Send an email with HTML, plain text, or AMP HTML content, with optional merge tags | Yes |
| `send_template_email` | Send an email using a saved template, identified by its slug | Yes |
| `list_emails` | List recently sent emails with filters and cursor pagination | — |
| `get_email_detail` | Show one sent email's full delivery timeline by its request ID | — |

Both send tools accept an `idempotency_key`. When the AI reuses the same key on a retry, the email is not sent twice (see [Idempotency](/learn/sending/idempotency)). Sent emails stay in `list_emails` for about 10 days.

## Scheduled Emails

| Tool | What it does | Destructive |
|-|-|-|
| `schedule_email` | Schedule an email for later delivery, with the same content options as `send_email` | — |
| `get_scheduled_email` | Show a scheduled email's state, delivery time, sender, subject, and recipients | — |
| `cancel_scheduled_email` | Cancel a scheduled email before it is sent | Yes |

The delivery time must be at least 5 minutes and at most 30 days in the future. See the [Schedule Email](/api-reference/emails/schedule-email) endpoint for the full set of options.

## Templates, Folders, and Projects

| Tool | What it does | Destructive |
|-|-|-|
| `list_projects` | List your team's projects, the containers for templates and folders | — |
| `list_folders` | List the template folders in a project, each with its purpose | — |
| `list_templates` | List templates, filtered by project, purpose, or folder | — |
| `get_template` | Show a template's details by ID or slug | — |
| `get_template_html` | Get the rendered HTML, subject, and merge tags of a template's active version | — |
| `get_merge_tags` | List the merge tags a template expects, and which are required | — |
| `create_template` | Create a Custom HTML template | — |
| `update_template` | Replace a template's content and make the result the new active version | Yes |
| `delete_template` | Permanently delete a template and all its versions | Yes |

<Note>
  `create_template` takes a `purpose` of `transactional` (the default) or `campaign`, and the purpose can't be changed later. A [campaign](/learn/campaigns/introduction) can only send a campaign template, so ask for a campaign template when you're writing a newsletter or promotion.
</Note>

## Sending Domains

| Tool | What it does | Destructive |
|-|-|-|
| `list_sending_domains` | List sending domains with their verification status | — |
| `get_domain` | Show a sending domain's DNS status and the DKIM record to publish | — |
| `create_domain` | Register a new sending domain and return the DNS records to publish | — |
| `verify_domain` | Run DNS verification for a sending domain and store the result | — |
| `delete_domain` | Delete a sending domain, which stops all sending from it | Yes |
| `diagnose_sending_domain_dns` | Explain why a domain is still pending or failing verification, and whether to wait or fix a record | — |

## Webhooks

| Tool | What it does | Destructive |
|-|-|-|
| `list_webhooks` | List webhooks with their URL, event types, and delivery health | — |
| `get_webhook` | Show one webhook's configuration and last delivery times | — |

## Campaigns

| Tool | What it does | Destructive |
|-|-|-|
| `list_campaigns` | List campaigns with engagement stats, optionally filtered by status | — |
| `get_campaign` | Show one campaign with its stats, rendered HTML, and language overrides | — |
| `list_campaign_events` | List a campaign's opens, clicks, bounces, and other events | — |
| `send_campaign` | Send a draft campaign to its whole audience right away | Yes |
| `schedule_campaign` | Schedule a draft campaign, or move an already scheduled one to a new time | Yes |
| `unschedule_campaign` | Cancel a scheduled send and return the campaign to draft | — |

<Warning>
  `send_campaign` and `schedule_campaign` send real email to every recipient in the campaign's audience. Emails that have gone out can't be recalled.
</Warning>

## Local Server Differences

The local `lettr-mcp` package names its tools with hyphens instead of underscores (`send-email` instead of `send_email`). Otherwise it offers the same tools, with these exceptions:

| Remote server | Local server |
|-|-|
| `send_template_email` | No separate tool; `send-email` takes a `template_slug` |
| `list_sending_domains` | `list-domains` |
| `browse_email_events` | `list-email-events` |
| `check_sending_health`, `diagnose_sending_domain_dns` | Not available |
| `get_analytics`, `list_template_stats`, `browse_api_logs` | Not available |
| `list_tracking_domains`, `list_inbound_domains`, `list_storage_domains`, `list_api_keys` | Not available |
| Not available | `list-scheduled-emails` lists emails waiting to be sent |
| Not available | `auth-check` validates the configured API key |
| Not available | `health-check` checks the Lettr API status |
